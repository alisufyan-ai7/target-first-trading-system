# Build and Deployment Roadmap

_Last updated: 2026-09-23_

Do not jump from an attractive backtest directly to a fully autonomous live account.

## Phase 1 — Context/specification recovery

- preserve original conversation/system context;
- preserve video evidence;
- investigate original Engine A recovery under a frozen reproduction protocol;
- resolve experiment numbering and superseded assumptions;
- freeze equivalent-sizing rules.

**Status: COMPLETE.**

EXP-014 concluded that the original EXP-002 implementation is not honestly recoverable from the surviving evidence. This is a closed recovery finding, not permission for further post-hoc benchmark fitting. Equivalent-sizing methodology is frozen in `docs/PNL-EQUIVALENT-SIZING.md`.

## Phase 2 — Reproducible strategy engines

For each engine:

- exact versioned specification;
- deterministic candidate generation;
- persisted candidate/trade ledger;
- data-source/version metadata;
- tests against future-looking logic;
- development / validation / holdout separation.

No recovery variant is promoted as the original Engine A. The current Phase-2 requirement is to create at least one **new prospectively frozen, causal, reproducible engine** and validate it without using EXP-002 as a parameter-fitting target.

**Current phase: Phase 2 — Reproducible strategy engines.**

## Phase 3 — Multi-market economic normalization

- document broker/venue contract specifications;
- use the frozen engine-conditioned native target-distance methodology;
- calculate equivalent lot size;
- enforce structural-risk/margin/notional gates;
- define target ladder.

**Methodology status:** frozen by EXP-014 Part B. Broker/symbol-specific contract economics remain to be documented when validated engine/market pairs reach this phase.

## Phase 4 — Target-first ranker

Input should normally be candidates generated by validated strategy engines.

Build/calibrate target-first probabilities, expected net USD value, target-rung selection, cross-market ranking, and correlation/common-factor control.

## Phase 5 — Portfolio simulation

Simulate concurrent opportunities, daily -USD 40 normal stop, -USD 60 emergency ceiling, +USD 150–200 profit-state behavior, partials/runners, realistic costs, zero-signal days, and correlated exposure.

Evaluate daily-distribution consistency, not only total P&L.

## Phase 6 — Independent-feed validation

Re-run frozen finalists on at least one independent feed.

Preferred eventual broker-specific path: MetaTrader 5 history from the intended broker where available.

Do not tune separately until a feed looks good.

## Phase 7 — Paper/demo live scanner

Run on live data with no real-money execution and record every candidate, rejection, probability/EV, theoretical trade, MFE/MAE, and daily state.

## Phase 8 — Signal-only mode

The system sends actionable signal packets but does not execute.

## Phase 9 — Human approval / semi-automatic mode

The system prepares orders; user explicitly approves execution.

Validate broker mechanics, spread/slippage, sizing, and operations.

## Phase 10 — Fully automatic execution

Only after robust historical evidence, independent-feed confirmation, realistic cost modeling, stable forward/demo evidence, validated risk controls, monitoring, and kill-switches.

## Continuous requirements

- versioned strategy specs;
- reproducible data provenance;
- persistent candidate/trade ledger;
- monitoring and failure recovery;
- audit trail;
- secrets outside Git.
